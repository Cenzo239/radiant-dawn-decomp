# Game-data guard

This repository must never contain game data: disc files, files extracted or decompressed from
the disc, generated port data, exported game text, saves, screenshots, or the HD texture pack.
`check_game_data.py` refuses such files before they reach git.

## Install (once per clone)

```
sh tools/guard/install.sh
```

This installs a `pre-commit` and a `pre-push` hook and builds the local hash index. The hooks
run a copy of the checker kept in `.git/fe10-guard/`, so they work on every branch and in every
worktree, including branches that do not have `tools/guard/` yet. Run the installer again after
changing anything in `tools/guard/`. An existing foreign hook is kept as `<hook>.local` and still
runs first.

## What is refused

| rule | refuses |
|------|---------|
| hash | content identical to any file under `orig/RFEE01/` (the extracted disc), `build/` (except objects/sources), `../private/` (saves, playtest references), `~/Library/Application Support/fe10_host/` (mods incl. HD pack and font mod, NAND), and the folders in `$FE10_USER_DIR`, `$FE10_NAND_DIR`, `$FE10_SAVES`, `$FE10_PLAYTEST_REFS`, `$FE10_SHOT_DIR`, `$FE10_CLOUD_DIR`, `$FE10_GUARD_EXTRA`, `.git/fe10-guard/roots.txt`. Symlinks (e.g. the HD pack's links to the upscale outputs) are followed. `build/` is not indexed (it contains copies of tracked source). |
| path | `orig/RFEE01/**`, `private/**`, `mods/**`, `*hd-textures*`, `*sharp-font*`, `*playtest_refs*`, `*/saves/*`, `*fe10_host/*` |
| type | image, texture, Nintendo container, audio/video, disc image, save and archive extensions |
| magic | Yaz0, U8, RARC, TPL, BRSTM/BRSAR/…, BRRES, BRLYT/BRLAN, RFNT, THP, banners, Wii/GC/WBFS/RVZ images, PNG/JPEG/DDS/…, ELF, zip/7z/gzip |
| binary | any NUL byte in the first 8 KB |
| marker | first line says `GENERATED by tools/port/gen_data.py` or `Do not commit`; `tools/mods` table headers |
| size | more than 3 MiB (`--max-size`, `FE10_GUARD_MAX_SIZE`) |
| link | (pre-commit) symlinks to absolute paths, the disc or the fe10_host folder |

`allow.txt` lists paths that may skip the type/magic/binary/marker/size rules (docs
screenshots). Nothing skips the hash or path rule.

The index (`.git/fe10-guard/index.tsv`, never committed) stores path, size, mtime and git blob
id of every game-data file; only new or changed files are hashed again, so after the first build
a check takes about a second. Rebuild by hand: `python3 tools/guard/check_game_data.py --index`.

## Manual checks

```
python3 tools/guard/check_game_data.py --tree HEAD          # every file of a tree
python3 tools/guard/check_game_data.py --range origin/main..HEAD
python3 tools/guard/check_game_data.py --history            # every blob on every ref
```

`git commit --no-verify` skips the commit hook; the push hook checks every new commit again,
and the `game-data-guard` GitHub workflow checks the pushed tree (without the hash rule, CI has
no disc files). If something did get pushed, removing it from the latest commit is not enough:
the history has to be rewritten.
